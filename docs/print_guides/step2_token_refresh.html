Layer 2: FastAPI Refresh Endpoint & Token Rotation Algorithm

FastAPI Router Implementation — backend/app/routers/auth.py
Refresh Endpoint Logic — auth.py (Lines 80-106)
@router.post("/refresh", response_model=TokenResponse)
async def refresh(payload: RefreshTokenRequest, db: DbSession) -> TokenResponse:
    # Step 1 — Decode and validate incoming refresh JWT signature & expiry
    try:
        claims = verify_token(payload.refresh_token, "refresh")
    except TokenValidationError as error:
        raise HTTPException(
            status_code=status.HTTP_401_UNAUTHORIZED,
            detail="Invalid or expired refresh token",
        ) from error

    # Step 2 — Verify user still exists and is active in PostgreSQL DB
    result = await db.execute(select(User).where(User.id == claims["sub"]))
    user = result.scalar_one_or_none()
    if user is None:
        raise HTTPException(status_code=status.HTTP_401_UNAUTHORIZED, detail="User not found")

    # Step 3 — Token Rotation: Issue a brand-new access & refresh token pair
    return TokenResponse(
        access_token=create_token(user, "access"),
        refresh_token=create_token(user, "refresh"),
    )

Layer 4: Flutter JwtInterceptor & 401 Silent Retry Engine

Mobile Dio Interceptor — lib/core/network/api_client.dart
JwtInterceptor Handling HTTP 401 — api_client.dart
class JwtInterceptor extends Interceptor {
  @override
  void onError(DioException err, ErrorInterceptorHandler handler) async {
    // 1. Intercept HTTP 401 Unauthorized errors from any API endpoint
    if (err.response?.statusCode == 401) {
      try {
        // 2. Attempt silent token refresh via POST /api/v1/auth/refresh
        final newTokens = await _refreshTokens();
        
        // 3. Update request headers with new access token
        err.requestOptions.headers['Authorization'] = 'Bearer ${newTokens.accessToken}';
        
        // 4. Retry the original failed HTTP request transparently
        final response = await _dio.fetch(err.requestOptions);
        return handler.resolve(response);
      } catch (_) {
        // 5. If refresh fails (expired refresh token), clear keys & auto-redirect to /login
        await _secureStorage.deleteAll();
      }
    }
    return super.onError(err, handler);
  }
}
ELI5 Interceptor: If the user is using the app and their 15-minute token expires mid-action, `JwtInterceptor` catches the `401` error behind the scenes, gets a fresh token, and retries the action instantly so the user never gets logged out!

Step 2 Debugging & Token Rotation Security Checklist

Troubleshooting & Security Checklist
Issue / Error Symptom Root Cause Backend / Database Fix
HTTP 401 "Invalid or expired refresh token" Refresh token 7-day expiration elapsed or token signature invalid User must log in again with username & password at POST /auth/token.
HTTP 401 "Type mismatch: expected refresh" Access token passed to POST /refresh instead of refresh token Verify Postman JSON body contains refresh_token, not access_token.
Infinite Loop on 401 Retry /refresh endpoint itself returning 401 without exemption in interceptor Exempt /api/v1/auth/refresh path from triggering the 401 retry interceptor.
PostgreSQL "User not found" on Refresh User record deleted or ID modified in database while refresh token active Return HTTP 401 to force client token cleanup and redirect to login screen.
