3. Backend Architecture, Database Schemas & Security Constraints

FastAPI Routers & Service Logic
  • Authentication Router: Uses bcrypt.verify() via Passlib and enforces 72-byte password limits.
  • Token Rotation Service: Issues 15-minute access tokens and 7-day refresh tokens; checks PostgreSQL before rotation.
  • Borrower Service: Encapsulates _audit_state() to redact PII (Name, Phone, ID) before staging AuditLog rows.
  • Loan Calculator Engine: Uses Python Decimal with ROUND_HALF_UP to generate Reducing Balance Amortization.
PostgreSQL Database Schemas
  • users → id (UUID), username (Unique Index), hashed_password, role, is_active.
  • borrowers → id (UUID), first_name, national_id (Unique Index), phone, status.
  • loans → id, borrower_id (FK), original_principal (Numeric 12,2), status.
  • loan_installments → id, loan_id (FK), due_date, principal_amount, interest_amount.
  • audit_logs → Immutable table storing user operations and redacted entity states.

4. Critical Financial & Security Rules

Core Guidelines for Lending System Engineering
1. Financial Decimal Precision: Never use standard floats for currency. Always use Python Decimal('10000.00') and Numeric(12,2) in SQL to eliminate penny drift.
2. Mandatory PII Audit Redaction: Never write plain borrower names, national IDs, or phone numbers to system logs. Redact all PII to [REDACTED] in audit JSON.
3. Idempotent Network Origination: Pass unique request_id with loan creation calls so retried network requests return existing loans without creating duplicates.
